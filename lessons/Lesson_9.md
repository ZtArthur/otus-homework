## Описание / Пошаговая инструкция

### Пункт 1. Добавление `ReaderWriterLockSlim`

Возьмите класс `SimpleStore` из ДЗ №1. Добавьте в него приватное поле:

```csharp
private readonly ReaderWriterLockSlim _lock = new ReaderWriterLockSlim();
```

Модифицируйте методы `Set`, `Get` и `Delete` так, чтобы они использовали этот лок:

- `Get` должен использовать блокировку на чтение (`EnterReadLock` / `ExitReadLock`)
- `Set` и `Delete` — блокировку на запись (`EnterWriteLock` / `ExitWriteLock`)

Обязательно используйте конструкцию `try...finally` для гарантированного освобождения блокировки.

### Пункт 2. Добавление полей для статистики

Добавьте в `SimpleStore` три приватных `long` поля для хранения статистики:

```csharp
_setCount
_getCount
_deleteCount
```

Создайте публичный метод или свойство (например, `GetStatistics()`), которое будет возвращать кортеж:

```csharp
(long setCount, long getCount, long deleteCount)
```

---

### Пункт 3. Реализация сбора статистики

Модифицируйте методы `Set`, `Get` и `Delete`. Внутри каждого метода после успешного выполнения основной операции инкрементируйте соответствующий счётчик. Используйте:

```csharp
Interlocked.Increment(ref _fieldName)
```

для потокобезопасного увеличения счётчиков.

---

### Пункт 4. Реализация `IDisposable`

Реализуйте в классе `SimpleStore` интерфейс `IDisposable`. В методе `Dispose` освободите ресурсы, занимаемые `ReaderWriterLockSlim` (вызвать его метод `Dispose`).

---

### Пункт 5. Написание тестов на многопоточность

Создайте новый юнит-тест (или добавьте в существующий). Напишите тест, который:

1. Запускает несколько задач (`Task.Run`) параллельно
2. Часть задач вызывает метод `Set`, другая часть — `Get`
3. Проверяет, что после выполнения всех задач данные в хранилище корректны и не произошло гонки состояний
4. Проверяет, что счётчики статистики показывают правильные значения
